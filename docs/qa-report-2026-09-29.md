# Findings and fixes

## Blocker — FIXED

**Hagerigna hymn #121 is placeholder test data.**

- Title `"የመዝሙር ርዕስ"` ("Song Title"), author `"ሙከራ መዝሙር"` ("Test Song"),
  lyrics `"መዝሙር 1 መዝሙር 2\nመዝሙር 3 መዝሙር 4\n"`. Bundled in
  `assets/data/database/HagerignaData.json`, visible on any offline-first
  install before the first API sync completes.

**Fix applied.** Removed the entry across all three parallel arrays
(`song_author_text`, `song_text`, `song_title_text`) — Hagerigna is now 120
hymns bundled. `HagerignaParser` still loads it correctly. Updated tests
that asserted the old count (`test/core/bundled_content_test.dart`,
`test/features/hymns/data/local_data_source_test.dart`) from 121 → 120.

## Major — NEW FINDING (not in first report) — FIXED

**English-title search silently broken for the 1975 hymnal on offline
first launch.**

Discovered while writing the new
`test/core/search_duplicated_english_titles_test.dart`. `SdaParser` reads
`new_title_en` (2004 English titles) but has never read `old_title_en`
(1975 English titles). Every hymn from the 1975 book got
`english_title_old: ''` on the offline/bundled path, so searching for a
1975 hymn by its English name returned zero results.

**Fix applied.** Added `oldEnglishTitleArray` alongside
`newEnglishTitleArray` in `SdaParser`, wired `old_title_en` from the JSON,
and made `english_title_old` per-book. New test passes for the two 1975
duplicated titles that now surface correctly.

## Major — WITHDRAWN (false positive in the first report)

**"76 uncategorised 2004-book hymns"** — this was wrong. My initial
regex over `lib/core/constants/hymn_categories.dart` missed the multiline
`HymnCategory(...)` entries. On re-parsing with `DOTALL`, the file has
**31 categories** covering **1–325 with zero gaps**. Verified against the
file's own `validate()` function. The Categories tab surfaces all 325
hymns; no fix needed. **Withdrawing this finding.**

## Major — FIXED (test coverage for PR #19)

**`hymnal_audio_handler.dart` was at 5.3 % coverage** — precisely the
file PR #19 modified to fix the two beta audio bugs (task-removal and
notification-dismiss stopping playback). A future regression would slip
through CI.

**Fix applied.** Added `test/core/audio_handler_lifecycle_test.dart` with
four structural guards:
1. `onTaskRemoved` calls `stop()` before delegating to `super`.
2. `onNotificationDeleted` calls `stop()` before delegating to `super`.
3. `AndroidManifest.xml` still declares `android:stopWithTask="true"` —
   without it, `onTaskRemoved` never fires.
4. The processing-state listener still calls `stop()` on `completed` — the
   "one hymn at a time" contract.

Chose the structural approach because the handler's constructor wires up
a `just_audio` `AudioPlayer` that would need a fully-mocked platform
channel to instantiate in a widget test; that would be more fragile and
add more surface area than what it tests. The structural test breaks the
moment either `stop()` call is removed.

Verified the guard bites: removed `await stop();` from `onTaskRemoved` →
test 1 failed. Reverted → all four pass.
